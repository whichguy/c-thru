# Holistic review — findings (c-thru)

Generated by a multi-agent audit (206 agents: 10 subsystem finders → 3 perspective-diverse adversarial
skeptics per finding, majority vote → completeness critic). 65 candidates → **48 confirmed** (≥2/3 skeptics
agreed real after independently reading the code). Severity: **6 critical, 12 high, 19 medium, 11 low**.
IDs `C1..C48` match the audit; `votes=n/3` is skeptic agreement. Verify each premise live before fixing.

## Headline: the gov (USGov Chinese-origin) filter is systemically incomplete

`best-cloud-gov` / `best-local-gov` (and gov-*based* custom modes) are supposed to block Chinese-origin
models. The audit shows the filter is shallow and full of holes — this is the dominant, highest-severity
cluster and the recommended first fix.

**Root cause A — the runtime filter runs in exactly one place, conditionally.** The only request-path block
is `applyModeFilter` at `claude-proxy:~4817`, gated behind `if (capChain)` (i.e. only when
`fallback_chains[hwTier][capKey]` exists). `resolveBackend`/`resolveProfileModel` apply no gov filter.
Consequences:
- **C3 (critical, 3/3)** — primary capability→model path has no gov filter at all.
- **C5 (critical, 3/3)** — when a capability has *no* `fallback_chains` entry (the shipped config's state), the gov block is skipped → Chinese model served in gov mode.
- **C4 (critical, 3/3)** — the runtime fallback cascade (`tryFallbackOrFail`: `fallback_to` walk, `fallback_chains` loop, `tryGlobalDefaultFallback`) dispatches the first non-cooldown candidate with no gov filter.

**Root cause B — the pattern set is start-anchored and incomplete** (`CHINESE_ORIGIN_PATTERNS`, `model-map-resolve.js:72`).
- **C2 (critical, 2/3)** — `^qwen`, `^glm`, `^kimi` match only bare prefixes; provider-prefixed slugs like `qwen/qwen3-coder`, `z-ai/glm-4.6` (the repo's *own* OpenRouter naming) bypass it. `thudm/` is the old Zhipu slug; current GLM ships `z-ai/`.
- **C15 (high, 2/3)** — missing families: minimax, yi/01-ai, baichuan, internlm, ernie/baidu, hunyuan/tencent, step/stepfun, doubao/bytedance.
- **C33 (medium, 3/3)** — name-only matching: a Chinese model behind a neutral alias/backend (e.g. `model_routes['fast']→api.deepseek.com`) escapes; `filterFor` ignores the `modelRoutes`/`backends` it's handed.

**Root cause C — validation only checks custom-mode override keys.**
- **C6 (critical, 3/3)** — `model-map-validate.js:617-628` inspects only `entry[customModeName]`, never the built-in `entry['best-cloud-gov']`/`entry['best-local-gov']` keys. A Chinese model placed directly on a gov key validates clean.
- **C37 (medium, 2/3)** — validation never checks `llm_profiles` model values against `model_routes`; an unknown model silently falls through to localhost Ollama at runtime.

**Root cause D — the CLI tools disagree with the proxy and each other (parity).**
- **C16 (high, 3/3)** — `c-thru-explain` shows gov slot picks as `BLOCKED` that the proxy actually dispatches.
- **C36 (medium, 3/3)** — `c-thru-resolve` and `c-thru-config-helpers` print the blocked model with no gov filter at all.
- **C46 (low, 2/3)** — explain reports `served_by=(null)` even when the proxy would find a compliant fallback.

**Gov test-coverage gaps (all 3/3):** C13, C17, C18 (gov mode + Chinese primary, no `fallback_chains` — the
real shipped bypass), C7/C34 (provider-prefixed + missing-family blocking), C26 (gov-*based custom mode*
end-to-end proxy test — only the pure fn from commit `a1dccb0` is covered).

> Note: commit `a1dccb0` (this session) made `isGovMode` detect gov-*based* custom modes and threaded
> `config` through `filterFor`/`applyModeFilter`/`resolveLocalFallback`. That was necessary but the audit
> shows the filter it feeds is itself applied conditionally and matches incompletely — so the deeper holes
> remain.

## Other security findings
- **C12 (high, 3/3)** — incoming Anthropic OAuth/API key forwarded **verbatim to a non-Anthropic backend** when host derivation fails and no explicit auth is set (`applyOutboundAuth` passthrough branch, `claude-proxy:904-952`). Credential leak. (Critic gap G2: no regression test.)
- **C28 (medium, 3/3)** — `debug_print_final_claude_command` (`c-thru:3491-3495`) prints the live subscription **OAuth bearer token in cleartext** to stderr when `C_THRU_DEBUG` is set. Mask it.
- **C19 (medium, 3/3)** — any `/v1/messages` body containing literal `[[c-thru-agent:<known-agent>]]` reroutes that request (sentinel honored anywhere in body, only anti-spoof is "name is a known agent"). Indirect-prompt-injection / routing spoof. *(Design-level — surface.)*
- **C23 (medium, 3/3)** — `POST /c-thru/mode` and `/c-thru/reload` are unauthenticated on the shared loopback port; a second local process can flip a shared proxy out of gov mode. *(Design-level — surface.)*
- **C8 (high, 3/3) / C21 (medium, 3/3)** — predictable world-readable `/tmp/c-thru-effective-<md5>.json` overlay written via `writeIfChanged` (`model-map-layered.js:186-194`) with no `O_EXCL`/no `lstat` → local symlink-follow config injection (routing redirection). (Critic gap G3 pins the write site.)

## Correctness / robustness
- **C11 (high, 3/3)** — Gemini upstream connection error with no configured fallback **hangs the client** (`up.on('error')` ignores `tryFallbackOrFail`'s return, never sends 502). Mirror `forwardAnthropic:1887-1893`.
- **C9 (high, 2/3)** — Gemini non-2xx path gates the cascade behind `if (backend.fallback_to)`, skipping `fallback_chains`/local-terminal/global-default (divergence from Anthropic + its own connection-error path).
- **C10 (high, 2/3)** — Gemini stream ending without a `finishReason` leaks an unterminated content block (no `content_block_stop`/`message_delta`).
- **C32 (medium, 3/3)** — `forwardGemini`/`geminiHttpRequest` set `options.timeout` but register no `'timeout'` handler → hung upstream never aborts.
- **C45 (low, 2/3)** — empty-base `@sigil` (`@anthropic`) → empty `effectiveModel` forwarded upstream; proxy regex `/^(.*)@/` inconsistent with `isCloud`'s `/^(.+)@/`.
- **C30 (medium, 2/3) — CONFLICTED:** finder says the SIGHUP `_fallbackChain` reset (`claude-proxy:1547`) is dead/harmful; critic gap **G6 contradicts** it (reload bumps `CONFIG_VERSION`, so it fires). Needs manual resolution — do not auto-fix.
- **C35 (medium, 2/3)** — `resolveProfileModel` returns null/503 when a mode entry is a tier-object present-but-missing-the-active-tier, without base/best-cloud fallback. *(Already documented as intended this session; decide: validate tier completeness vs fall through.)*
- **C44 (low, 2/3)** — `tryLocalTerminalFallback` de-dups a logical model name against the set of concrete (rewritten) names → can re-dispatch an already-tried terminal.

## Config layering / lifecycle
- **C1 (critical, 2/3)** — bash `sync_layered_profile_model_map` (`c-thru:146`, called from 765) merges the project tier into the **shared** `~/.claude/model-map.json`, defeating the Node two-pass design that keeps the profile project-free. Cross-session routing leak. *(Verify carefully — bash↔Node interaction.)*
- **C20 (medium, 2/3)** — `model-map-edit.js` diffs against a non-synthesized baseline → v1.2 synthesized `models[]`/`tool_capability_to_profile` leak into `model-map.overrides.json` on edit of a legacy-shape config.
- **C27 (medium, 2/3)** — `arm_proxy_cleanup`'s `trap ... EXIT` clobbers the ephemeral-session cleanup trap → shadow tmpdir leaked on every proxied launch.
- **C24 (medium, 3/3)** — `uninstall.sh` uses logical `pwd` (L31) vs physical `pwd -P` (L97) → orphaned symlinks when the repo path has a symlinked component.
- **C48 (medium, 2/3)** — `POST /c-thru/mode` pins `CLAUDE_LLM_MODE` but a later reload removing that custom mode silently degrades gov→best-cloud (resolve.js stderr only).
